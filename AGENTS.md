# AGENTS.md — blog-daniel-ramirez-io

Guidance for agents (and humans) working in this repo.

## What this is
The Astro static site for `blog.daniel-ramirez.io`. Migrated from Hugo. First
greenfield implementation of the LUFS website-portability contract. Plan lives in
`danialrami/agent-knowledge` → `docs/infra/blog-astro-migration/`.

## Ground rules
- **Content is authored in Obsidian**, not here. `src/content/**` is regenerated by
  `sync_obsidian-to-astro.sh` (rsync `--delete`). Do not hand-edit posts as the
  source of truth — edit the vault. Structural/scaffold files are fair game.
- **Single source of truth for slugs:** `src/lib/slug.ts` (Hugo title-slug parity).
  Used by routes and the RSS feed. Don't reimplement slugging elsewhere.
- **Schema is the contract:** `src/content.config.ts`. Extend it (don't bypass it);
  `astro build` fails closed on invalid frontmatter — keep it that way.
- **Build once, deploy many:** never add a host-native build. `scripts/build`
  produces `dist/`; `scripts/verify` proves it; `scripts/package` freezes the
  release; CI publishes to the `site` branch. Hosts are swappable adapters.
- **Verify before done:** a green `npm run build` is not enough — `scripts/verify`
  must pass (index, required routes, URL parity, asset budget, secret scan).

## Frontend seam (Amacher)
Style `src/layouts/*`, the chrome data in `src/config/site.ts`, and the tokens in
`src/styles/tokens.css`. The prose slot (`.prose`) covers headings, code blocks,
tables, and injected `<audio>/<video>/<iframe>` players.

## Don't
- Don't commit `dist/`, `release/`, or `node_modules/` (see `.gitignore`).
- Don't hardcode the canonical domain in content — it lives in `astro.config.mjs`
  and `site.yaml`.
- Don't force-push a build to a host branch (the old Hugo anti-pattern). CI owns publish.
